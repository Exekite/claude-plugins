# Respond to actual refusals

This selected guidance is built from the current refusal codes. Read the returned details and state; the code alone does not establish rollback, a refunded charge, or a completed job.

| Returned codes | Next action |
|---|---|
| `FILE_CONFLICT` | The file at `details.path` is not what the operation expected: `details.actual_sha256` is its current SHA-256 (null when it is absent) and `details.expected_sha256` is the hash you sent. Read that file again, reconcile your change with what is there while preserving concurrent work, and retry with the current hash. In a build turn, a `write`, `delete` or `move` onto a file of the starter waiting screen (`scenes/Main.tscn` and `main.gd`) installed when the turn locked the game also accepts the hash that file had before the turn opened (null if it was absent), but only while it still holds those starter bytes and the turn has not changed it; `literal_replace`, `unified_patch` and a move away from it take its current hash. The message says when a refused file is that starter. A conflict met by `resume_turn` means the draft cannot be restored there: read its files with `get_failed_attempt` and reapply them in a new turn. |
| `FILE_UNAVAILABLE` | `details.path` names a requested file that does not exist where it was read (the turn's draft, the current project or the given `revision`), and `details.paths` lists every missing path of a batch read; nothing in that batch was read. Check the names with `list_files`, then read again without the missing paths. Opening a build turn removes files left from the starter template, such as AGENTS.md, so do not expect them in its draft. |
| `REVISION_CONFLICT`, `SEQUENCE_CONFLICT`, `MANIFEST_CONFLICT`, `MODEL_CHECKPOINT_CONFLICT`, `LISTING_REVIEW_INVALID_AUTHORITY` | Read the latest affected files, turn, asset, or manifest and reconcile the intended change. Preserve concurrent work; use the new guard only after inspecting it. `LISTING_REVIEW_INVALID_AUTHORITY`: the listing review answered for settings saved after the ones checked; read `get_ship_settings` and check again with its `manifest_revision`. |
| `IDEMPOTENCY_CONFLICT`, `IDEMPOTENCY_KEY_REUSED` | The operation key already names a different request body. Read the original job for that key; use a new key only for genuinely new work, never to change a request whose outcome you have not read. |
| `ACKNOWLEDGEMENT_UNKNOWN`, `EXECUTOR_STOPPED`, `RELEASE_ACKNOWLEDGEMENT_UNKNOWN`, `KIT_ACKNOWLEDGEMENT_UNKNOWN` | The operation's outcome is unknown: it may have reached the project runtime or the release builder, but the executor stopped or never confirmed it, and calling again with the same key returns this same outcome. Inspect `get_turn` (state and sequence), the project's revision and history, and `list_charges`; for a release or kit request, `list_releases` and `get_release`. If they show the work took effect, do not repeat it; if they show it did not, retry once with a new operation key. Do not start replacement work while that is still unclear. A failure whose `details.dispatched` is false is different: nothing was sent (see `EXECUTOR_UNAVAILABLE`). |
| `EXECUTOR_UNAVAILABLE`, `AGENT_BUSY` | `details.dispatched` false: the project runtime could not be reached (still starting, failed to start, or busy finishing another change), so this operation was not sent and nothing changed. The job is failed and final for its key; there is nothing to look for in `get_turn`, history or charges. Retry after `retry_after_s` (15 seconds, or 5 for `AGENT_BUSY`) with a new operation key for a call that takes one. Without `details.dispatched`, the project's runtime cannot open changes right now: read the original job and the project, retry once with a new operation key only when `details.retryable` is true, and otherwise report it. `ACKNOWLEDGEMENT_UNKNOWN` is the uncertain case, not this one. |
| `AGENT_BOOTING`, `WORKSPACE_FOREIGN`, `FOREIGN_WORKSPACE`, `FOREIGN_SESSION` | Exekite Studio did not carry out this request: the game's workspace was still starting (`AGENT_BOOTING`), or it was serving another session of the project (the others). Retry in a few seconds (after `retry_after_s` when given): a refusal the call returned directly (no job) with the same key, a failed job with a new operation key. If it repeats, report the code instead of working around it. |
| `CANCELLED`, `OPERATION_CANCELLED_BEFORE_EXECUTION` | The change was stopped before it started (by the owner in Studio, or by a cancellation of this job), and its draft is unchanged. Start it again only if the user asks, with a new operation key. |
| `PROJECT_NOT_FOUND`, `PROJECT_SCOPE_REQUIRED` | The project is not available to this connection (it does not exist, belongs to someone else, or is outside the granted games), or creating a project needs access to all games. Do not guess other identifiers or reveal anything about the requested one. Offer the games `list_projects` returns; changing the grant is the user's choice in the normal connection flow. |
| `WORKSPACE_BUSY`, `ITERATION_IN_FLIGHT` | Another writer holds this game or account; `details.holder` names it when known: `assistant_turn` (an assistant turn, possibly your own), `studio_change` (a change requested in Studio), `platform_change` (a change Exekite started itself, such as the game's first build), `release_work`, `web_export`, `asset_change` or another change. A call that opens a turn's writer lease (`apply_changes`, `start_check`, `start_game_test` or `submit_turn`) waits at most about 45 seconds in the authoring queue behind such a change, then is refused with `details.waited_s` and its turn unchanged. Land or roll back your own turn before a separate transaction; a draft parked across another change cannot resume. Otherwise wait the returned `retry_after_s` (about a minute when none is given), then retry once: a refusal the call returned directly (no job) with the same key, a failed job with a new key and, for apply_changes or submit_turn, `expected_sequence` from `details.sequence`. Do not override, cancel or wait indefinitely on someone else's writer. Meanwhile, `list_files`, `read_files`, `search_files` and `view_images` can read committed files with `revision` instead of turn_id (a ready turn's base is `details.base_revision`); other reads wait for the writer. |
| `ACTIVATION_FAILED` | The turn's writer could not start. Unless `details.workspace_restored` is false (the turn is then closed: follow `TURN_CLOSED`), nothing ran and its draft is unchanged (`details.turn_state` shows ready or parked). Plan, balance, settlement and busy refusals arrive under their own codes in this table, or name one in `details.cause`; follow that row. Otherwise, when `details.retryable` is true, retry after `retry_after_s` with a new operation key (the failed job keeps its key) and, for apply_changes or submit_turn, `expected_sequence` from `details.sequence`; when it is false, read `get_turn` and report the refusal. Do not open a duplicate turn while this one can still resume. |
| `TURN_NOT_ACTIVE`, `GAME_TEST_NOT_ACTIVE` | The turn's draft or its Game Test is not running. Call the tool in `details.activate_with` with `details.required_arguments`, then repeat the call: resume_turn restores a parked or idle draft, a turn that never opened its writer opens it with its first apply_changes, start_check or start_game_test, and Game Test reads need start_game_test. A build turn's reads wait for its writer too (`details.purpose` build), because opening it installs the game's starting files (project.godot and the waiting scene): open it with `start_check` profile parse, then read with turn_id and write against the hashes you read. When `details.retry_after_s` is given instead, the turn is opening or landing: wait that long and read again. `stop_game_test` on a turn with no running test answers `already_stopped` rather than this code. |
| `WEB_EXPORT_MISSING` | This workspace has no Web export right now: a turn landing or `create_preview_link` makes one, and a workspace restart discards it. A Web Game Test plays that export, never the current draft: test the draft with `start_game_test` target native (`details.alternative`). Nothing started and the turn's writer did not open. Do not retry target web until a new turn lands, or `create_preview_link` has prepared an export while no turn holds its writer. |
| `TURN_CLOSED` | This turn has ended (landed, aborted or failed) and cannot be resumed or changed. Read `get_turn` and, for unlanded work, `get_failed_attempt`. To continue, start a new turn from the current revision and reapply what is still needed; do not present it as the old draft resumed. |
| `TURN_EXPIRED` | A turn can resume only until its logical deadline, 6 hours after `start_turn` (`logical_deadline` in `get_turn`), although its parked draft stays readable for 24 hours. After the deadline, read the files with `get_failed_attempt`, start a new turn from the current revision and reapply them; do not claim the expired draft resumed. |
| `LEASE_EXPIRED`, `DRAFT_PARKED`, `RESUME_REQUIRED` | Read the saved turn and resume only when its returned state and current base permit it (`details.activate_with` names the call). Status reads do not extend the lease. |
| `DRAFT_EXPIRED`, `REPLAY_REFUSED` | Report the retained state and failure. Reconcile from current source; do not claim an expired or rejected replay was restored. |
| `DRAFT_LIMIT` | The turn's durable draft would grow past its 15 MiB limit (`details.projected_draft_bytes` against `details.limit_bytes`; `get_turn` reports `draft_bytes` against `draft_limit_bytes`), so that write or operation was refused and undone. Land the turn with `submit_turn` before adding more, or keep files and models smaller. When the message says the turn is closed, read the project before starting a new turn. |
| `GATE_BUDGET`, `NO_FINAL_GATE`, `SUBMIT_BUDGET`, `PARSE_BUDGET`, `PLAYTEST_BUDGET` | Stop consuming the exhausted budget. Report the actual last result and recover or close the turn as its state allows. Parking does not reset counters. |
| `PATH_REFUSED`, `WRITE_AUDIT_FAILED` | Keep platform-managed and private paths outside authored changes. Use the supported operation or revise the change; do not evade the path rule. |
| `TREE_CHANGED_DURING_CHECK` | The game's own code changed its source files while the check ran, so the turn was rolled back. Find the code that writes into the project at runtime (for example saving to `res://`), make it write under `user://` instead, and reapply the change in a new turn. |
| `GAME_NOT_AUTHORED`, `ALREADY_BUILT`, `DIMENSION_CONFLICT` | `GAME_NOT_AUTHORED`: a build turn's draft does not hold an authored game yet (the message names what is missing; the starter waiting screen does not count): write the game's scene and scripts, check them, then submit. `ALREADY_BUILT`: the game already has its first build; use `start_turn` with purpose edit, and `set_game_design` only for an unbuilt project. `DIMENSION_CONFLICT`: a game's 2D or 3D dimension is fixed once its design is saved; keep it, or create a new game for the other dimension. |
| `TURN_LANDED`, `UNSAVED_CHANGES`, `WORKSPACE_UNMEASURABLE` | `TURN_LANDED`: a landed turn is saved as a verified revision and cannot be aborted; `restore_revision` returns the game to an earlier verified revision when the user asks. `UNSAVED_CHANGES`: a restore needs a workspace without unsaved source changes, so land or roll back the open turn first. `WORKSPACE_UNMEASURABLE`: the workspace could not be checked for unsaved changes; retry once shortly and report it if it repeats. |
| `PLAN_NOT_INCLUDED`, `QUOTA_EXCEEDED` | The account's plan does not include this operation (creating or editing games, for `PLAN_NOT_INCLUDED`). `estimate_cost` and the four paid generation tools answer it before anything is quoted, held or charged, and a stored quote is refused the same way when the plan lapsed after it. Say so plainly; listing, reading and playing existing games remain available. Do not retry, work around it with another project, or talk about plans, prices or payments; the account owner manages the account in Exekite Studio. |
| `PROJECT_LIMIT_REACHED` | The account cannot create another project. Do not retry the creation; offer to continue in an existing game the user picks from `list_projects`. |
| `USAGE_LIMIT_REACHED` | A fair-use limit of the account's plan was reached, so this request did not start and nothing was charged; a turn's draft stays as it was. `details.dimension` names the limit and the rows below say what to do for each, with `details.limit`, `details.observed` and, when waiting clears it, `details.resets_at` (a Unix time in seconds) or `details.retry_after_s`. Tell the user what could not run and when it can run again. Do not retry before then, split the work or move it to another project to get around the limit, and do not talk about plans, prices or payments; the account owner can manage the account in Exekite Studio. A retry of a refusal the call returned directly (no job) keeps its key; a failed job retries with a new operation key. |
| `USAGE_LIMIT_REACHED` | `details.dimension` `open_projects`: the account already has its maximum number of games open in their cloud workspaces (`details.open_projects` names them), so this game's workspace did not start. Offer to continue one of those games instead; otherwise the person can close the other game in Exekite Studio, or the request can be retried about two minutes after that game's last activity. |
| `USAGE_LIMIT_REACHED` | `details.dimension` `app_builds`: the account has used today's app builds, so this build did not start. Retry it after `details.resets_at`. |
| `USAGE_LIMIT_REACHED` | `details.dimension` `shares`: the account has published its maximum number of games. Unpublishing one with `revoke_share` frees a place, but only when the user asks for that; a temporary preview link (`create_preview_link`) needs no place. |
| `USAGE_LIMIT_REACHED` | `details.dimension` `previews`: the account has its maximum number of temporary preview links for other games. Retry after one of those links expires. |
| `USAGE_LIMIT_REACHED` | `details.dimension` `cancels`: the account cancelled its daily maximum of requests, so new agent and media work waits until `details.resets_at`, the next UTC day. Playing, sharing and cancelling still work. |
| `USAGE_LIMIT_REACHED` | `details.dimension` `cancel_pause`: the cost of the account's cancelled requests paused new agent and media work until `details.resets_at`. Playing, sharing and cancelling still work. |
| `USAGE_LIMIT_REACHED` | `details.dimension` `rollbacks`: the account's paid attempts that rolled back today reached its daily maximum (`details.limit`), so new paid work waits until `details.resets_at`, the next UTC day. Rolled-back work is never charged. |
| `USAGE_LIMIT_REACHED` | `details.dimension` `mcp_calls`: the account's connected assistants have used today's calls. Progress checks on running work (`get_job`, `wait_for_job`, `list_jobs`, `get_turn`) and cancellations still work; other calls resume after `details.resets_at`. |
| `PROJECT_NAME_EXISTS` | Another of the account's games, including a deleted one, already uses this title. Choose a different title, or continue in the existing game when the user meant that one. |
| `DIMENSION_NOT_INCLUDED` | The plan does not include the capability in `details.capability` (for example 3D games, a release target, or generated media). Offer the in-plan alternative: `details.alternative` (a 2D game instead of 3D) or a release target `get_ship_status` lists. For a 3D game, `estimate_cost` and the paid generation tools answer this before anything is quoted, held or charged (`details.alternative` 2d). For release builds, `desktop_export` means Windows, Mac and Linux builds, `android_export` means Android or iOS builds, and `store_release_kits` means the store release kits (Google Play, itch.io, Steam, Web H5, CrazyGames and Poki); the release targets `get_ship_status` lists stay available. `details.capability` `generated_media` means the account's plan includes no Exekite-generated images, sprite sheets, sounds, music, 3D models, key art or store art, whatever its balance; `estimate_cost` and the four paid generation tools answer it before anything is quoted, held or charged. Tell the user plainly that the plan does not include generated media (the account owner can review the plan in Exekite Studio), then continue with procedurally created art and sound, which edit turns can change, or with the person's own files (`begin_file_upload`, then `attach_game_asset`). Never present procedural art as the generated asset, and do not suggest another plan, prices or payments. `details.capability` `game_edits` means the account's plan builds one game, once: a game cannot be changed after its first accepted build, and no other game can be created or built, so nothing was started or charged. The account's games can still be listed, played, shared from their links and exported for the web. Tell the user plainly what the plan does not include (the account owner can review the plan in Exekite Studio), and do not suggest another plan, prices or payments. Do not retry the same request. |
| `BALANCE_EMPTY` | The account's available balance does not cover this request's maximum charge, so it was not started and nothing was charged. When the refusal names them, `details.needed_micros` is what the request needs available and `details.available_micros` what is, in micro-dollars like `get_balance`. Tell the user which operation could not run. The account's games can still be read, played and shared from their links; a smaller generation that fits `get_balance` is an option only when the user asks for one. Do not retry or split the request to get around the refusal, and do not suggest adding funds; the account owner can manage the account in Exekite Studio. |
| `PAID_OPERATION_IN_PROGRESS` | Either a paid generation on this account is still in progress (`details.phase` running, or it ended without success and awaits settlement), and no paid generation or game change can start until it clears; or one that succeeded is still settling its charge, and the maximum charge it holds leaves too little of the balance for this request (`get_balance` shows the held amount). A paid generation that succeeded does not otherwise block, so wire its asset right away. Wait the returned `retry_after_s` (`settles_after` is when it should clear, or for a running generation when to check again; a charge normally settles 5–10 minutes after the paid work ends), then retry once with a new operation key; when the 15-minute quote of a waiting generation has expired meanwhile, call `estimate_cost` again for the same parameters and start it with the new `estimate_id`. When the wait is longer than you can hold this reply, tell the user when to continue instead of polling. Keep generated assets, and check `get_balance` and the original job instead of generating again. |
| `BALANCE_PENDING` | Earlier charges on the account are not priced yet, often because a change is still running (`details.changes_in_progress`), so no paid generation can reserve funds. Wait the returned `retry_after_s`; if the quote has expired by then, call `estimate_cost` again for the same operation and parameters and start it with the new `estimate_id`. `get_balance` shows the pending charges. Do not split the request or generate again to get around it. |
| `ESTIMATE_EXPIRED`, `ESTIMATE_MISMATCH` | When `details.reason` is `used`, the quote was already spent by the operation in `details.used_by_job_id`: read that job with `get_job` (and `get_balance`) first, and do not quote or generate again while it is queued, running or succeeded. Otherwise a quote lasts 15 minutes, covers one generation and must match the exact parameters: call `estimate_cost` again for the same operation and parameters and start it with the new `estimate_id`. |
| `ESTIMATE_UNAVAILABLE`, `RECIPE_CHANGED` | `ESTIMATE_UNAVAILABLE`: no quote was made and nothing was held or charged, so do not call the paid tool. `details.quote_http_status` and `details.quote_reason`, or the message, say why. Change what the refusal names and quote again, or report the blocker; never present procedural art as the generated asset. `RECIPE_CHANGED`: the project or the recipe changed after the quote; call `estimate_cost` again for the same request and start it with the new `estimate_id`. |
| `CONCURRENCY_LIMIT`, `SERVICE_BUSY`, `ADMISSION_REFUSED` | Too much work is in flight for this account or for Exekite. Check your own running jobs with `get_job`, wait the returned `retry_after_s`, then retry the same call with the same operation key; do not change the key or start other work to get around the limit. |
| `RATE_LIMITED` | This connection made too many calls in one minute (300 at most), or, with `details.window` `minute`, the account's connected assistants together made more calls in a minute than its plan allows. Nothing was admitted: wait `retry_after_s` (10 seconds for the connection's limit), then repeat the same call; the same operation key is fine. Progress checks on running work (`get_job`, `wait_for_job`, `list_jobs`, `get_turn`) and cancellations count only toward the connection's limit, never the account's. Poll less: `wait_for_job` holds a job until it is succeeded, failed, cancelled or interrupted, for up to `max_wait_seconds` (at most 45 seconds, default 20). |
| `INSUFFICIENT_SCOPE`, `SCOPE_REQUIRED` | This connection was not granted the permission the tool needs (`details.required_scope`, `details.tool`), so nothing was started or changed. The host can ask the person to reconnect Exekite with that permission; until then do not retry, and do not reach for other tools to get around it. With `details.client_registered` false, this assistant registered without that permission, so reconnecting it as it is set up cannot add it: tell the person to set it up to request that permission, then connect it again. Reconnecting makes a new connection, so jobs, turns and cost estimates from this one are not visible to it. |
| `TOOL_UNAVAILABLE` | This tool is not available on this connection or server right now (for example a feature that is turned off), and nothing ran. Do not retry it; use another listed tool for the task, or tell the user it is unavailable. |
| `REQUEST_TOO_LARGE` | One call carries at most 1 MiB (`details.limit_bytes`; this call was `details.actual_bytes`), and nothing was started or changed. Split the change into several `apply_changes` calls, a few files per call, or send several smaller calls. |
| `OPERATION_FAILED`, `INTERNAL_ERROR` | `OPERATION_FAILED` (from the project runtime) or `INTERNAL_ERROR` (from Exekite's server): the operation failed without a specific reason, and its own text is in Exekite's logs, where Exekite finds it from the operation's `job_id`. Read the turn or project state first. If the change did not take effect and `details.retryable` is true, retry once with a new operation key. If it repeats, report the tool and the failed operation's `job_id` (through `send_feedback` when the user wants to contact Exekite); do not guess at the cause. |
| `SERVICE_INTERRUPTED` | A temporary Exekite platform error interrupted this call before it answered; nothing about the request was refused. Wait `retry_after_s`, then send the same call again with the same operation key (not a new one): an operation already admitted under that key is never started twice, and the retry picks it up. If it keeps failing after a few tries, read the operation with `list_jobs`: a job still queued either starts or ends with `OPERATION_NOT_STARTED` within about 21 minutes of the call, and only then is a new key right. If it repeats, report the tool and when it failed, with the operation's `job_id` when `list_jobs` shows one. |
| `OPERATION_REFUSED`, `EXECUTOR_REFUSED` | Studio or the project runtime refused this operation for the reason in its message, and nothing changed. Follow that reason (a release setting, an account state or a rule the message names); do not resend the same request. |
| `NOT_FOUND`, `FORBIDDEN` | Exekite Studio refused this step for this project, and nothing changed. `NOT_FOUND`: the item it was asked for does not exist; read the listing it came from again and use an id it returns. `FORBIDDEN`: this connection may not make this change, which only the person can make in Exekite Studio; tell them, and do not retry it. |
| `DESIGN_NOT_LANDED`, `TUNABLES_NOT_LANDED`, `ASSET_NOT_LANDED`, `MEDIA_NOT_LANDED`, `RESTORE_FAILED`, `RECOVERY_FAILED`, `HELPER_NOT_INSTALLED` | The change did not land. `details.rolled_back` true: nothing from it was kept. `rolled_back` false with `retryable` false: the rollback did not complete, so read the project's files before any other change. `details.cause` {code, message, details}: follow that code's row (for example `REVISION_CONFLICT`, `ASSET_IMPORT_FAILED` or `MEDIA_PROVIDER_FAILED`). `details.gate_summary` and `details.failed_checks`: the validation gate's own errors (GDScript parse and runtime errors); fix them in an edit turn or report them before retrying. No `cause`, `gate_summary` or `failed_checks` in `details`: no specific reason; retry once with a new operation key when `retryable` is true. A `MEDIA_NOT_LANDED` after its paid request was sent never advises a retry: `list_recoverable_assets` shows whether its output can be recovered without paying again. A `RECOVERY_FAILED` or `HELPER_NOT_INSTALLED` without details states the step's own reason in its message. |
| `MEDIA_PROVIDER_FAILED` | `details.reason` `unreachable` or `provider_failed`: the request may have reached the media service, so never resubmit the same operation; `list_recoverable_assets` and `list_charges` show whether it ran. `refused` (with `details.http_status`): nothing was generated. `unavailable`: nothing was generated; try again later. |
| `MEDIA_DELIVERY_FAILED` | `details.reason` `provider_failed`: the provider could not generate the asset, and nothing was added to the game. `unreachable`, `refused` or `unavailable`: delivery failed, and if the job completed, `list_recoverable_assets` and then `recover_game_asset` bring its output into the game without paying again. |
| `MEDIA_IMPORT_FAILED`, `ASSET_IMPORT_FAILED`, `INVALID_DELIVERY` | A delivered or uploaded file could not be taken into the game (`details.reason` `import_failed`, `download_failed`, `integrity_failed`, `write_failed` or `path_refused`), so nothing was kept. For a paid generation whose job completed, `list_recoverable_assets` and `recover_game_asset` can try again without paying again; do not generate it again. If the import fails again, report the asset and the operation's `job_id`. |
| `MEDIA_TIMEOUT` | Delivery took longer than its limit (a sprite sheet 10 minutes, a 3D model 12, a sound 6, another image 3), so Exekite asked the media service to cancel it; that does not prove provider work or spending stopped. Do not resubmit: check `list_charges` and, once the job completes, `list_recoverable_assets` and `recover_game_asset` to bring it in without paying again. |
| `CANCELLATION_UNSUPPORTED`, `CANCELLATION_REQUIRES_EXECUTOR`, `CANCELLATION_UNCONFIRMED`, `CANCELLATION_REFUSED` | The cancellation did not complete, so the operation may still run or may have finished. Keep reading the original job with `wait_for_job` or `get_job` for its real outcome, and for a paid generation `list_charges`; do not start replacement work while it is unresolved. Only a queued job and an active turn's own steps can be cancelled. |
| `MODEL_OPERATION_FAILED`, `DESKTOP_OPERATION_FAILED` | The message is the Blender or Game Test desktop's own diagnostic: GDScript errors and game log lines are kept, project files appear as `res://` paths and other runtime paths as `<runtime>`, and Python tracebacks are removed. Fix what it names (for example a script error) and try the step again, or report it. |
| `MODEL_NOT_OPEN` | Open the registered model with `open_3d_model`, or create one with `create_3d_model`, in this turn before editing, previewing or saving it. |
| `PLAYTEST_INCOMPLETE` | The scripted playtest did not finish (`details.timed_out`, `details.code`, and `details.logs` with the game's own output). Fix the error the logs show, or shorten or correct the timeline, before running it again; each run counts against the turn's playtest budget. |
| `RESULT_TOO_LARGE`, `INVALID_MEDIA`, `MEDIA_LIMIT`, `IMAGE_STORAGE_UNAVAILABLE` | A result exceeded what Exekite can return or store. When a job failed with `RESULT_TOO_LARGE` and `details.result_recorded` is false, the operation itself finished but its result, over the 192 KB limit (`details.limit_bytes`), was not recorded: its effects remain, so inspect the project, turn or asset instead of repeating it. Ask for a smaller result (fewer files, narrower line ranges, or fewer frames, images, selectors or properties). |
| `ASSET_PREVIEW_UNAVAILABLE` | A registered-media read never starts the project's workspace, so nothing was read. `details.reason` `preview_preparing`: a reduced-texture preview of a large model is being made; read again after `details.retry_after_s` (about 5 seconds). Nothing in the game changes; do not loop more than a few times. `runtime_not_running`: the workspace is asleep; when the user wants to inspect the asset now, one `get_game_asset` call with project_id and asset_id and no turn_id starts it, then read again at the same revision. `runtime_unreachable`: it did not answer; read again shortly, and use that same `get_game_asset` call only if it persists. None of these means the asset is broken; do not retry in a loop. The owner can also open the asset in Studio's Assets tab. |
| `ASSET_READ_LIMIT` | The media is larger than an inline preview reads (`details.byte_size` over `details.limit_bytes`, or `details.file_count` over `details.file_limit`); the game still uses the full file. `details.reduced_preview` `unavailable`: the model is too large to preview, and no reduced preview can be made from it. Check the asset in the game itself with Game Test (`start_game_test` within a turn) instead, or tell the user it can be inspected in Studio's Assets tab. ## Other codes

A code without its own row above follows the first row below whose pattern it matches. Read its message and details first; they name the field, item or limit involved.

| Code pattern | Next action |
|---|---|
| `INVALID_*`, `UNSUPPORTED_*`, `*_INVALID*`, `*_UNSUPPORTED` | An argument is invalid, or an option is not supported; the message and details name the field and what is accepted. Correct that argument from the tool's schema and the message, then call again; never resend it unchanged. |
| `*_NOT_FOUND` | The named item does not exist for this connection: a mistyped or stale id, an item made through another connection (each connection sees only its own jobs and turns), or a file past its 30-day keeping period. Read the listing it came from (for example `list_game_assets`, `list_history`, `list_releases` or `list_jobs`) and use an id it returns; never guess ids. |
| `*_EXPIRED` | A link, upload, view or session reached its fixed expiry, and nothing else changed. When the user still wants it, make a new one with a new operation key (or a new `idempotency_key`); never reuse or repost the expired one. |
| `*_LIMIT`, `*_TOO_LARGE` | The request exceeds a size or count limit that the message and details name (for example `details.limit_bytes`). Ask for less: fewer or smaller files, frames, images or operations per call. Do not retry it unchanged, and do not shrink or regenerate an asset only to fit a preview. |
| `*_CONFLICT` | What the request was based on has changed (a file, asset, take, patch context or view). Read the current state again and redo the change against it; preserve work that is not yours. |
| `*_CHANGED` | Something the request depended on changed while it ran (the asset, upload, release profile, share, runtime or subscription). Read the current state and call again with the current values. |
| `*_REQUIRED` | A required input or step is missing, and the message names it (a saved design, a project_id, a store workspace, a verified game, an image or text file, or an operation key). Supply it and call again; when it is a step for the person in Exekite Studio, say so. |
| `*_UNAVAILABLE` | A service, stored file or capability this request needs is unavailable right now, and nothing changed. Retry once after `retry_after_s` (or about a minute); if it repeats, report the code and message instead of working around it. |
| `*_REFUSED` | Exekite refused this step for the reason in its message (a rule about models, releases, uploads, tunables, exports or a control lease), and nothing changed. Follow that reason; do not resend the same request. |
| `*_FAILED` | A step failed for the reason in its message, and its details say what was kept: read `details.rolled_back`, `details.retryable` and `details.cause`, and the job, turn or project, before anything else. Retry once with a new operation key only when `details.retryable` is true; otherwise report it with the operation's `job_id`. |
