# Watch, play, and inspect

Keep design decisions and source changes in the conversation. The companion is a focused view of the work already authorized in that conversation.

1. Admit the requested domain operation using its normal tool and stable operation key.
2. Call `create_companion_link` with `project_id`, `target: {kind: "job", job_id: "the-returned-job"}` and a stable `idempotency_key`, and give the user its `url`; the inline companion works only in ChatGPT today. Queued and running results are valid. Do not wait for Blender or Game Test to finish before opening its view.
3. Continue the work and inspect durable outcomes with `get_job` or `wait_for_job`. The UI follows its exact root job or acknowledged turn independently. Do not keep reopening it to poll.
4. A verified `create_preview_link` job supplies the playable build. Show that job as `{kind: "job", job_id}` or as `{kind: "preview", job_id, revision}` with the verified revision it was requested for, while it prepares or once ready; the companion automatically displays the authorized game when ready. A refused target returns the accepted form in its details. Actual player interaction pins that build while the agent continues. Browser audio still requires the person's gesture.
5. A completed model or registered asset can be inspected at the version its job returned. A Blender model uses `{kind: "model", job_id, model_id, revision}` with its 64-character checkpoint; do not confuse that checkpoint with a 40-character Git revision. Generated media such as an `add_game_asset` GLB uses `{kind: "job", job_id}` or `{kind: "asset", job_id, asset_id, revision}` with that `add_game_asset` job's own `job_id` (not the provider job id inside its result) and the revision that job returned before wiring, not a later `submit_turn` job or its landed revision. An asset target needs a verified game revision. `get_game_asset` with no turn returns the asset at the workspace's current revision, and a Ship settings save commits outside a turn and moves that revision past the last verified one; its asset target is then refused with reason revision_not_verified, and details.accepted_target names a job that returned the asset at a verified revision when one exists, usually its `add_game_asset` job. Calling `get_game_asset` again returns the same revision until another turn lands. Omit the asset hash: the fingerprint `read_asset_animation` returns pins only a repeat of that read. A refused target names its cause in details.reason and the accepted form in details.accepted_target. Draft assets also require the exact active-turn checkpoint sequence. Read real clip/frame metadata with `read_asset_animation`; do not invent animation names. Inline previews read at most 6 MiB and eight media files. A registered GLB model over 6 MiB (up to 32 MiB; generated models are often 8 to 11 MB) is shown and read as a reduced-texture preview, its textures at most 1024 px (512 px when 1024 does not fit), labelled in the result's `derivative` field; the game keeps the full model, so say the preview has reduced textures. While that preview is prepared, a read answers ASSET_PREVIEW_UNAVAILABLE with reason preview_preparing: the view retries by itself, and when you read it yourself, read again after details.retry_after_s. Other media over 6 MiB or eight files, or a model no preview can be made from (details.reduced_preview unavailable), is refused with ASSET_READ_LIMIT and its measured size: report that and verify the asset in a Game Test or in Studio's Assets tab instead. A sleeping workspace returns ASSET_PREVIEW_UNAVAILABLE with reason runtime_not_running, and the view never wakes it. When the person asks to inspect that asset now, one `get_game_asset` call with no turn starts the workspace; the open view then loads the asset by itself.

For a new game, make the first accepted playable version visible before long media or editing work: prepare its preview link and show the exact returned job. This is a verified snapshot; source writing is not a live game stream. After a meaningful playable revision is accepted, prepare an updated preview when the user is following the work. Preserve an existing playable view while generation runs or a watch session is unavailable. If Blender or Game Test fails before starting, explain that failure and offer the last prepared playable build rather than leaving an ended watch surface as the only result.

After completing requested game creation or editing, show the resultant accepted game automatically and introduce its objective and controls. A validation result is an intermediate status, not the delivery. Prepare/show the exact preview without another user prompt, follow its existing preparation job, and report a real failure if it cannot become playable. Temporary viewer/network failures should recover the authorized display automatically; recovery must not start another build, test, export or paid generation. Ended sessions, expired previews and revoked access are distinct from a temporary outage. A game that finished loading keeps running in the view after its preview link expires, with Restart disabled; restarting or reopening it needs a fresh preview.

The user's **Keep this view** selection is deliberate. Continue backend work without overriding it. **Follow activity** resumes following; an expired view can be rechecked but must not start another turn, test, export or paid generation.

Do not replace a pinned or actively played build with an updated preview or watch session automatically. Offer the new result so the user can switch. Prepare new snapshots only after an accepted revision or to replace an expired preview the user still wants; polling and page opening must not repeatedly export the game.

On this connection every view opens this way: call `create_companion_link` with the same `project_id`, target, and a stable `idempotency_key`. Return the companion link's `url` and explain that the same owner signs in to Studio. The link expires after ten minutes; the claimed viewing session lasts at most thirty minutes and stays bound to the original MCP grant. Reuse the key after an uncertain response. Once a link has actually expired, a newly requested handoff uses a new key. Never put a Studio or MCP token in a URL, chat, or command.

Blender is watch-only. Game Test human takeover is available only where the host advertises it and the person explicitly selects it. Let the server reject conflicting agent inputs while a person owns control. Playing a prepared browser build is separate from controlling the agent's running test.

Selected asset, clip, timestamp and revision references may be sent as text context. This does not establish image delivery. Direct image context is disabled pending actual host vision qualification; use **Save capture** and manual composer attachment when the person wants the assistant to see pixels. A VNC stream is visible to the person, not a continuous model observation channel. Use ordinary observation tools when reasoning from a screenshot.

If a format, runtime, host capability or version is unavailable, report that state. Do not generate replacement media, wake a sleeping workspace or repeat an operation just to populate the view. The one exception is in item 5: when the person asks to inspect an asset now, a single `get_game_asset` call may start its sleeping workspace.
